Scope and findings:
  The test imports the pinned upstream VirtualCart and MBC RTL. Migen simulates
  the actual cache, cache fills, clock-domain crossings, and write-through FSM.
  A memory-port model supplies backing-memory reads/writes and host changes.

  The production 256-line, 16-byte direct-mapped cache is used. Test payload
  reads visit both ends of every relevant cache line in tiles, attributes,
  and palettes, in receiver order. Tiles use the DMA request input; attributes
  and palettes use the CPU read input. Full CPU/HDMA instruction execution is
  outside this test's scope.

  Host changes to a previously cached bank demonstrably remain stale without
  eviction. Alternating complete payload banks 1 and 2 refreshes every tested
  line, including the indices shared by tiles, attributes, and palettes.
  Reading bank 3 offset 0 before bank 0 metadata refreshes the metadata line.
  A split metadata commit can expose a new sequence with the preceding bank;
  the receiver must reject reuse of its last accepted payload bank.
  Device writes at bank 0 offset 0x10 reach backing memory without changing
  the host-owned metadata line at offset 0.

Limitations:
  This run does not simulate the PSRAM arbiter/PHY, USB transport, the complete
  Game Boy CPU, or electrical timing. It does not establish physical-device
  frame rate or verify a firmware installation. The complete USB connection
  still requires testing on an actual Chromatic.

Reproduction:
  Use a checkout at the exact upstream revision above. Install Migen 0.9.2 and
  LiteX 2024.12 into a Python virtual environment, set CHROMATIX_SOURCE to that
  checkout, and run the unittest command with your Python executable.
  Allow roughly 90 seconds. Without CHROMATIX_SOURCE, unittest discovery skips
  this optional RTL suite; a skipped run is not equivalent to this passing run.
